## Collection and ownership

Admission first requires a pre-CREATE local generic mapping with explicit `FILE_READ_DATA | FILE_EXECUTE`, no `MAXIMUM_ALLOWED`, and supported pre-CREATE name/stream qualification. `SL_OPEN_TARGET_DIRECTORY` is rejected. A zero-initialized nonpaged completion context carries the Boolean and mapped mask; missing context is unavailable. Post-CREATE requires successful ordinary completion and rejects `STATUS_OPLOCK_BREAK_IN_PROGRESS`. `FileObject->ReadAccess` is only an additional consistency filter, not proof of `FILE_READ_DATA`. R7 still redundantly checks raw post-CREATE `FILE_EXECUTE`, which can wrongly reject a generic-execute request; fix and test this in the next package. Context must be PASSIVE_LEVEL with special APCs enabled, no top-level IRP, and no transaction. Directory, observed `STATUS_REPARSE`, final-target reparse attribute, paging-file, unnamed, alternate-stream, noncached and already-cleaned-up objects are excluded. These checks do not prove that no earlier path reparse occurred. Name/stream classification uses `FltGetFileNameInformation` and `FltParseFileNameInformation`, never the post-CREATE `FILE_OBJECT.FileName` buffer. The existing NTFS instance gate and the qualification controller's disconnected single-disk guest gate further restrict this experiment.

The driver reserves the complete bounded byte credit and holds a typed reference to the original open file object. It publishes an internal provisional entry before reads. A live process-create callback binds that exact object to PID plus process creation time. A provisional entry cannot expose bytes through the port. The reference prevents object-address reuse; it does not justify reading after cleanup.

Only the successful post-CREATE callback reads bytes, before returning to the caller. It uses explicit offsets and `FLTFL_IO_OPERATION_DO_NOT_UPDATE_BYTE_OFFSET`. There is no path reopen, deferred file read, image-notification I/O, section mapping, or wait for user mode. EOF and selected basic timestamps are checked again after the copy.

The completed buffer is exposed only when both copy completion and exact process binding exist. Process exit marks the entry and preserves completed bytes. Retrieval requires PID, process start, candidate ID after the initial lookup, offset and length. No kernel pointer or handle is exported. The reader saves a unique `.evidence.bin`, verifies its SHA-256 against the controlled source fixture, and acknowledges it. No preserved copy is executed.

Stop/disconnect detaches table entries. An in-flight copy retains its own buffer ownership and cannot republish after stop. Port reads hold a buffer reference while copying outside the table lock. Buffers are erased and freed after the last owner releases them. Every staging entry point acquires driver-owned rundown protection. Unload prevents new acquisitions, waits for existing acquisitions to finish, performs a final sweep, and proceeds with filter/port teardown. Synchronous reads are not forcibly canceled.

## Bounds and explicit limitations

- 64 candidate metadata slots and an independently enforced maximum of 16 in-flight copies (`ST_MAX_INFLIGHT`). Completed unbound entries may be evicted oldest-first; bound/in-flight entries are never capacity-evicted.
- Maximum 8 MiB per candidate, 32 MiB total logical byte-buffer credit; metadata overhead is additional.
- 64 KiB transfer/read chunks, at most 256 positive read iterations.
- Five-second publication deadline checked between reads and after final metadata validation. It cannot interrupt a read blocked below the filter.
- Thirty-second expiry is currently **activity-driven**, plus immediate stop/disconnect cleanup. An idle expiry timer remains required before broader use.
- Execute-only opens without explicit mapped `FILE_READ_DATA`, existing processes, unsupported file/context cases, capacity failures, and missing qualifying opens remain unavailable.
- Aggregate diagnostic reason/status counters are present. Per-event failure retention and product enrichment/response integration remain outstanding.
- Pre/post metadata equality does not prove a coherent immutable filesystem snapshot. Concurrent writes can escape those checks. The evidence describes raw backing bytes read during eligible post-CREATE and later bound to the process; it is not process memory or a claim of immutable executed content.
- Process-create callback association does not alone prove eventual successful process creation or execution. A later independently observed file operation from the same PID/start generation is required before product promotion to actor-operation evidence. The lab reader separately verifies successful child exit; product promotion is not implemented here.
- The diagnostic file ID is a volume-relative NTFS identifier, not a globally unique ID. The exact held file-object comparison is the binding mechanism.
- Reading adds process-launch latency. `DO_NOT_UPDATE_BYTE_OFFSET` restores the caller-visible offset, but lower filters may observe temporary offset changes. It is not I/O serialization.
- This diagnostic copies qualifying executable candidates before an alert threshold is known. It must not be enabled as general product collection without policy, performance, failure-telemetry and lifetime work.
