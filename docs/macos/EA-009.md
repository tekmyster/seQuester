# EA-009 macOS attribution increment — OPEN native acceptance

This source increment provides a managed provider seam, bounded evidence pipeline, raw evidence archive, per-event mapping and truthful policy/status handling. **It does not implement an Apple Endpoint Security ABI binding or establish working native attribution.** Production selection is `UnavailableNativeProvider`. The previous unmanaged helper launch path is retired from Monitors.cs because its availability could not establish the requested verified binding. No Apple security controls or machine configuration were changed.

## Capability and operator action

| Condition | Result and action |
|---|---|
| macOS / API unsupported | No native attribution; use an accepted host/API. |
| Native binding absent | Complete SDK verification and binding. This is the actual macOS production state in this increment. |
| Missing entitlement | Obtain Apple approval and the matching entitled signed build. |
| Missing Full Disk Access | Administrator approval through supported Apple controls is required. |
| Authorization denied / insufficient privilege | Inspect the actual client result and approved service identity; do not guess FDA from an unrelated error. |
| Subscription failed | Native attribution unavailable; inspect diagnostics. |
| Fixture running | Managed tests only; never native acceptance. |
| Queue/provider loss | Evidence incomplete; inspect cumulative counters and load. Restart clears current state, not historical loss counters. |
| Stopped / failed | No native coverage; start or repair the sensor. |
| FSEvents | File changes only. No process/open/read/copy attribution. No encryption inference. |

`fsevents` configuration explicitly requests detection fallback and may acknowledge that policy. `endpoint-security` configuration starts fallback but the MACOS-only policy guard rejects cache/acknowledgment until native subscription is available. Startup can continue with fallback. Existing enrollment, spool event IDs and dedup logic are unchanged. There is no automatic native retry loop: restart after installing an accepted binding is the recovery action. With this source alone, restart remains unavailable.

## Evidence contract

The future provider supplies a managed snapshot with original event ID/time, observed operation, raw provider bytes, source/target paths, optional sequence/global sequence, audit token identity, PID/PPID, executable, signing/team identity and real/effective/audit user/session IDs. These are semantic C# records, **not Apple struct layouts or enum constants**. Missing fields remain null. Native version/availability checks and token decoding belong in the future SDK-verified binding, not guesses in managed mapping.

Map only explicit open intent, write, modified close, delete, rename and permission facts. Read/copy/encryption are not inferred. Unknown operations and truncated or wire-incompatible paths are archived without an invented alert. Unicode paths are preserved; control characters are rejected. Raw evidence includes signing and full rename lineage that the unchanged wire schema cannot represent. The local content-addressed evidence ID links the existing additive EventAttribution record; raw data is not silently stuffed into unrelated server fields. Records remain partial or detection-only. Snapshot tokens never become response handles. No process termination is authorized by this adapter.

The callback accepts at most 64 KiB raw bytes and bounded strings, copies byte ownership and uses nonblocking TryWrite into a bounded queue. It performs no file IO or publication. Managed validation exceptions are contained. A single consumer persists the raw record before mapping/publication; archive or publish failure is counted and degraded. Quota exhaustion preserves old evidence and suppresses new publication. The caller must supply an existing private evidence directory; production has no active provider that writes it. The archive is a source seam, not a deployment-ready forensic custody system. Stop invalidates callback generations, stops the provider, completes/drains the queue and disposes deterministically. A future provider must guarantee bounded Stop/quiescence; arbitrary injected blocking sinks are not time-limited here.

## Exact external gates

1. Supply an authoritative Apple macOS SDK and record version, provenance and SHA256 of EndpointSecurity/ESClient.h, ESMessage.h, ESTypes.h and audit-token headers plus dependencies. No such headers were located on this Windows host. Web documentation is semantic evidence, not ABI verification.
2. On both intended macOS architectures compile SDK probes for every imported function signature, event/result constant, sizeof/alignof/offsetof, availability version and union field used. Implement a verified binding with notify subscriptions only; authorization-client result handling must distinguish actual results. No AUTH decision subscription exists here.
3. Validate message/actor/file/string-token lifetime and lengths, event-version fields, audit-token helpers, process identity and rename source/destination variants against those headers. Copy or retain/release within Apple's documented lifetime. Exercise actual subscription failure and clean unsubscribe/delete on all exits.
4. Obtain Apple entitlement approval, permitted signing identity/provisioning and distribution/notarization acceptance through the normal release process. The plist here is a template, not an entitlement grant. No signing, provisioning, FDA/TCC/SIP changes, system extension or install was performed.
5. Build and run on native macOS x64/arm64 with the approved entitlement and FDA. Exercise positive and denied startup, each event class and actor lineage, native malformed/version edges, loss/pressure, restart/shutdown and FSEvents fallback. Confirm ES-required policy remains pending until subscription. Windows fixtures cannot satisfy these gates.
6. Feed the verified provider into the existing adapter, prepare the private evidence directory, enforce resource bounds with real provider/sink behavior, expose native diagnostic/counter snapshots, and perform independent review before native acceptance. The retained baseline Native.cs response P/Invokes are unmodified and are outside the new unbound notification adapter.
