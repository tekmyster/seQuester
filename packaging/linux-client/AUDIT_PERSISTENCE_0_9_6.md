## 0.9.5 Debian compatibility failure and corrected authority

0.9.5 passed the scoped Ubuntu/auditctl3.0.7 pilot, but failed on Debian13.7/auditctl4.0.2 after installing one partial rule. The reviewed file included `-S all`; the helper mistakenly omitted it in the actual add command. Libaudit4.0.2 inferred a permission-specific syscall mask from perm=rwa; old3.0.7 relied on auditctl's default-all fallback. Post-add strict verification failed normally, with Expected6/verified Added0 but one actual live rule. Rollout removed only that exact partial rule and restored the original0.8.0 endpoint, enrollment and all canary hashes. Fleet expansion stopped.

0.9.6 explicitly preserves `-S all` before the path/permission fields in the actual add arguments. It does not relax coverage equality: an already-installed expanded or reduced list remains a pre-mutation conflict requiring administrator review; the helper never removes or silently blesses it. Do not infer full preservation from an arbitrary syscall list. This is an approved-authority argument fix, not a version-specific list allowlist.

## Retained 0.9.4 status correction

The previous 0.9.4 native first-run gate failed before mutation because its status parser incorrectly required exactly two tokens on every auditctl status line. Standard audit-userspace 3.0.7 emits `loginuid_immutable 0 unlocked`; the subsequent unhandled managed exception caused SIGABRT. All six rules remained unchanged. Rollout restored 0.9.3 and manually restored rules after its known restart gap; enrollment and canary hashes were preserved. Do not retry the 0.9.4 archive unchanged.

0.9.6 adds a bounded parser that accepts the annotated optional loginuid feature while strictly validating unique numeric enabled/PID fields; malformed or duplicate identities still fail. Failures now return normal exit code 1 rather than an unhandled abort, and protected status records a fixed FailureStage. Parser fixtures use the exact observed host output. Successful parsing is not native reconciliation or lifecycle acceptance.

## What changes

`sequester-audit-rules.service` now runs the .NET agent's `--audit-reconcile-rules`, not a blind `auditctl -R`. It is bound to auditd with `BindsTo` and `After`; `PartOf` propagates restart. Enabling the unit installs `auditd.service.wants` membership so each auditd start pulls it in. The oneshot has no automatic retry. A failed reconciliation does not stop unrelated auditd logging or erase rules. These relationships follow the [systemd unit contract](https://man7.org/linux/man-pages/man5/systemd.unit.5.html).

The root-owned, mode-0600 `/etc/ransomfree-client/sequester-audit.rules` remains the only desired-rule authority. No rules are placed in `/etc/audit/rules.d`. Supported syntax is exact file-path `always,exit`, b64/b32, `perm=rwa`, key `sequester_canary`; live `-S all` and `-F key=` are normalized. Paths must use ASCII letters/digits, slash, underscore, dash and dot and be under configured folders. Other rule shapes or ambiguous reserved-key rules fail rather than being rewritten.

Before mutation, the helper validates the full desired set and path availability. It lists live rules, refuses unexpected/duplicate owned entries, adds only missing reviewed entries, and compares live owned/unrelated inventories before and after each addition. It uses typed arguments with fixed OS auditctl, bounded output and a 15-second command deadline. It never issues `-D`, deletes rules, runs a shell command from the rules file, or blindly retries. Partial additions remain visible for administrator review; an explicit later run recomputes the missing set. Reconciliation is not an atomic kernel transaction and cannot prevent another privileged administrator changing rules after verification. [auditctl reference](https://man7.org/linux/man-pages/man8/auditctl.8.html).

Status `/var/lib/sequester-audit/rules-status.json` records run ID, expected/verified-added counts, success/failure and auditd boot/PID/start identity. `--audit-health` now refuses failed or previous-auditd-instance reconciliation status. A passed status is a snapshot, not continuous kernel rule attestation. Out-of-band `augenrules --load`, rule deletion without an auditd restart, and HUP-only reload are not automatic reconciliation triggers. Perform an explicit reviewed reconciliation after those operations.

## Fail-visible recovery and rollback

On any failure stop expanding the pilot and retain protected status, journal and inventories. No automatic rollback is attempted. A failed command may have added a reviewed subset before failing. Inspect exact live entries; never run a broad clear or remove unrelated rules. Once the cause is corrected, an explicitly approved loader restart recomputes missing entries. Manual repair is recovery evidence, not a passed automatic persistence test.

For binary rollback: enter protected maintenance, stop endpoint/collector and stop/disable the candidate loader before restoring only the recorded prior selector and seQuester unit/drop-in/enablement/configuration state. On the existing Ubuntu integration this means the accepted0.9.5 baseline with its zero-argument Native AOT plugin and previously accepted6-rule authority. On restored Debian it means0.8.0 without the new integration: disable only the new plugin/loader, review and remove only exact newly installed seQuester entries using scoped inverses, and retire only newly introduced definitions recoverably. Preserve unrelated audit rules/plugins. Run daemon-reload and the approved auditd procedure as required for that baseline; verify its expected endpoint/integration state. Keep MDWE/ProtectHome unchanged. Preserve current queues/cursors/identities and canaries, not stale snapshot replacements. If any different baseline was recorded, stop and adapt the plan explicitly rather than assuming a version or deleting pre-existing definitions.

If attribution must instead be disabled, use the previously approved detection-only rollback: disable only the seQuester plugin and loader, preserve unrelated plugins, and remove only reviewed exact seQuester entries using their scoped inverse operations when explicitly authorized. Never activate an old JIT plugin or weaken auditd. Record degraded coverage. Keep old/new immutable payloads and all evidence; no recursive deletion is required.
