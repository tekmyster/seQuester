## Architecture and prerequisites

auditd -> root-owned launch-relay.sh (zero plugin arguments) -> distribution setpriv (drop relay capabilities, then exec) -> C# Native AOT RansomFree.AuditRelay -> private AF_UNIX socket -> separate .NET RansomFree.LinuxAgent --audit-collect -> protected inbox -> endpoint durable management queue -> management server -> configured integrations.

The relay retains root UID but no permitted/effective/bounding/inheritable/ambient capabilities and has NoNewPrivileges set before its runtime starts. The collector remains capability-free. Otherwise Linux commoncap denies the collector's /proc/PID/exe identity check when the relay has a larger permitted set. This failure was reproduced as PeerExecutableRead/EACCES and corrected with unchanged UID/executable/path checks in the isolated fixture. No CAP_SYS_PTRACE was added. See audit-relay/TRANSPORT-FIXTURE-EVIDENCE.json; this fixture is not live auditd/canary acceptance.

Collector and relay both use root:root real/effective credentials; matching GIDs are also required by Linux /proc access checks. The collector unit must not retain old Group=rfclient overrides. Inbox ownership remains root:rfclient 2750 so created packets inherit the endpoint-readable group. The zero-argument /bin/sh launcher validates root caller, root-owned current selector, canonical versioned release and all executable/ancestor ownership/modes, rejects writable/symlinked release components and unexpected arguments, then execs setpriv. This is OS bootstrap, not a second application implementation. Use `sudo /opt/ransomfree-client/current/audit/launch-relay.sh --check` for a no-start preflight.

The 0.9.0 direct JIT audit plugin is deployment-blocked on the pilot with auditd MemoryDenyWriteExecute=yes. **Do not disable auditd MDWE or alter its sandbox.** Only the Native AOT relay runs as its child. The managed collector is a separate systemd service with its own sandbox and no inherited auditd MDWE. `--audit-dispatch` remains a diagnostic stdin mode; never configure it as an auditd plugin.

Management must support attribution-v1 before activation (0.6.4 server or compatible newer build). Older receivers retain unsupported evidence in bounded queues. Install distribution auditd, `libauparse.so.0` (Ubuntu: libauparse0), /bin/sh, coreutils id/stat/readlink and util-linux /usr/bin/setpriv. Application code remains C#/.NET; these and auditctl/shell bootstrap scripts are OS dependencies. The unchanged Native AOT relay reports 0.9.1/protocol v1 inside endpoint 0.9.4. Current replacement is Linux x64/glibc; ARM64 still requires its own native relay. Containers are build/test runners, not certified sensor hosts.

## Monitoring choices

- inotify, audit disabled: detection only, no actor proof.
- fanotify, audit disabled: PIDFD and explicitly partial best-effort enrichment.
- inotify plus audit: historical syscall actor evidence without fanotify capabilities or process response.
- fanotify plus audit: complementary live response handles and historical credentials, after native acceptance. Events are not heuristically merged by PID/time.

## Evidence meaning and limits

Kernel boot/timestamp/serial identity assembles records through upstream libauparse. PID/PPID, executable/comm, UID/eUID/fsUID/login UID/session, syscall/outcome are carried when available. Optional PROCTITLE capture can contain secrets. Local names are best-effort `/etc/passwd` snapshots; LDAP-only accounts may stay numeric.

Full attribution means core actor fields plus an observed terminal EOE **or PROCTITLE** and the expected PATH count. Upstream libauparse 3.0.7 finalizes on either and discards a later standalone EOE; timeout-only or incomplete sets remain partial. Reference: https://raw.githubusercontent.com/linux-audit/audit-userspace/v3.0.7/auparse/auparse.c . This does not establish every enrichment field, universal operation coverage, or malicious intent.

An audited open is intent, not proof that bytes were read or copied. mmap, kernel I/O, rename/hardlinks and remote filesystems need native validation. SMB/NFS may identify the local server daemon, not the remote person/workstation. Historical PIDs never authorize a stop; only existing approved live PIDFD response paths may do so. No response rights are inferred from later PID reuse.

## Bounds, gaps and recovery

Relay stdin buffering is 256 chunks of at most 8192 bytes (about 2 MiB), continuously drained while the collector is disconnected. Loss counters/gap frames reset partial parser assembly; they count chunks, not exact kernel records. Collector buffering is 2048 chunks; disk packets are at most 256 KiB and bounded by configured count/size. A 16 MiB parser feed window can reset incomplete sets and reports a gap. Kernel/auditd drops must be checked separately. This is not infinite or lossless storage.

Status records distinguish collector/relay identity, frames, bytes and packet sequence. `TransportFailureCount` and `LastTransportFailure` retain a bounded category/stage/native errno/PID/timestamp; the journal logs at most once per ten seconds, without exception messages or audit payloads. A previous failure remains historical even after recovery. Health does not prove rule coverage. Unexpected receiver exit fails the collector for restart; missing libauparse fails closed. Parser lifecycle/feed/callback/destruction stays on one OS thread.

The endpoint advances its cursor only after exact active-canary observations enter its durable management queue. Deterministic EventIds support identical replay. Preserve inbox identity, cursor, queues and enrollment during upgrades. Do not clear evidence to fix version mismatch. Inbox PATH records may include other paths in the keyed syscall; govern access and retention accordingly.

To retire: disable only this plugin, stop/disable its rule-loader to prevent reapplication, remove ONLY exact previously installed sequester rules using their reviewed -d inverses, stop/disable the collector, and set Audit.Enabled=false through protected maintenance. Retain the protected rule file/inbox for recovery. Do not assume stopping a oneshot removes rules or auditd restart clears them. Never clear unrelated audit policy. Endpoint uninstall does not remove this separately managed integration.
