# Managed offline alert storage

Agent 0.6.3-dev / MSI 0.6.3 uses a transactional SQLite FIFO for enrolled endpoint events. The earlier 0.6.1 MSI remains an immutable pre-change checkpoint. Old agents retain the fixed 1,000-event JSON queue and do not honor the new capacity policy.

Administrators configure Policies / Offline alert storage per group. Defaults: 10,000 alerts and 128 MiB of serialized event payload. Supported ranges: 1,000–1,000,000 alerts and 32–1,024 MiB. Limits are independent; reaching either prevents a new enqueue. Existing alerts are never evicted to make room. If limits decrease below current usage, the backlog continues delivering but no new events can be added until it drains below both limits. Cached policy restores capacity after agent restart; unassigned endpoints use defaults. The read-only tray reports count, count limit and payload usage/limit.

The agent always attempts management delivery regardless of syslog configuration. Each enqueue and acknowledged FIFO-prefix removal commits a SQLite transaction. Missing/invalid receipts, interrupted requests and connectivity failures retain pending records for retry. Duplicate server acceptance is supported by stable event IDs; a server acknowledgement lost in transit may cause a resend. A valid receipt removes only the exact submitted prefix. Recovery drains up to ten batches of 100 per 15-second delivery cycle. This is not a delivery latency SLA.

The queue database is events-ENDPOINTID.db under the existing protected agent state directory, with SQLite WAL/full synchronous mode. Limits measure payload, not total disk usage: database pages, indexes, journals and retained legacy files require additional free space. Deleting acknowledged rows allows page reuse; this does not shrink files immediately. Disk exhaustion, corruption or capacity failure is reported; no finite queue guarantees unlimited lossless capture. Old queued records are preserved, but newly generated events may be unqueued at capacity. Existing activity logs have their own rotation and are not a substitute for replayable queue entries.

On first use, a valid legacy events-ENDPOINTID.json (maximum 1,000 events / 32 MiB) is imported transactionally. The original file is retained unchanged. A committed migration marker prevents reimport on restart. Invalid/duplicate/oversized legacy content blocks migration and remains untouched. Do not downgrade to a JSON-only agent after migration: it cannot see new SQLite evidence and could replay stale legacy records. Back up state while the service is stopped, including any SQLite sidecars; restore only the matching endpoint identity on the same machine for DPAPI credentials. No automated downgrade or backup workflow is implied.

Compilation is not runtime acceptance. Three-pass QA, crash/disk-pressure recovery, migration and long-outage stress tests are deferred in QA.md.
